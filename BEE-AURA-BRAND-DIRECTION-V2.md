# Bee-Aura Brand Direction v2

Status: Direction lock before page-by-page polish  
Scope: Visual/demo standard only  
Rule: Keep page layouts. Improve professional finish.

## Core decision

Bee-Aura should look like a serious AI business operating system, not a cartoon mascot dashboard.

The product should feel:
- calm
- premium
- controlled
- operational
- trustworthy
- useful to real UK service businesses

The system should not feel:
- childish
- gimmicky
- game-like
- mascot-led
- cheap AI clip-art
- like a random dashboard template

## Name and positioning

Keep:
- Bee-Aura
- Lead Recovery OS
- AI business operating system direction

Preferred naming in serious product areas:
- Bee-Aura Lead Recovery OS
- Bee-Aura AI Operations OS
- Bee-Aura for Service Businesses

Avoid making the bee the main product personality.

## Logo direction

Do not use cheap text initials like:
- BA
- AI

Do not use:
- cartoon bee face
- smiling mascot
- antennae
- childish wings
- thick cartoon outlines
- cheap robot emoji
- AI clip-art
- over-glowing tech icon

Preferred direction:
- premium wordmark
- abstract bee / aura / signal mark
- geometric mark that works small
- simple mark plus wordmark
- serious SaaS identity

## Assistant direction

The assistant should be separate from the main logo.

Preferred assistant name:
- Aura Assistant

The assistant should feel:
- calm
- intelligent
- professional
- controlled
- supportive

Assistant should appear only where useful:
- AI suggestions
- message drafts
- approval panels
- help/support areas
- dashboard assistant panel

## Image direction

If images are used, they should look premium and realistic.

Good image directions:
- high-end abstract AI assistant visual
- premium dark SaaS assistant render
- subtle futuristic operations assistant
- service-business control centre visual
- realistic but not human-heavy
- professional, calm, dark navy/blue/gold

Avoid:
- cheap cartoon bees
- childish mascots
- smiling robot heads
- generic AI stock art
- overly sci-fi glowing faces
- anything that makes the product feel fake

## Colour direction

Keep:
- dark navy / blue base
- muted gold as primary action colour
- blue as system/technology colour

Improve:
- reduce glow
- reduce shine
- reduce cartoon/game feel
- make cards cleaner
- make borders calmer
- make typography more mature

## Layout rule

Keep the layouts the user selected.

Do not rebuild page layouts unless a final audit proves the layout damages the product.

Allowed changes:
- logo cleanup
- mascot reduction
- spacing polish
- better images
- better typography
- colour maturity
- button consistency
- data realism
- CSS cleanup

Not allowed without approval:
- changing chosen page layouts
- removing core page sections
- replacing a whole page design just because of branding

## Page-by-page cleanup order

1. App shell / sidebar
2. Home page
3. Dashboard
4. Leads
5. Messages
6. Bookings
7. Customers
8. Follow-Ups
9. Reviews
10. Activity Log
11. Error Log
12. Settings

## Final goal

The demo should become the visual/product blueprint for the real Bee-Aura system.

Before real backend work, the demo must feel:
- professional enough to show customers
- consistent across every page
- realistic with coherent fake data
- aligned with the future SaaS product
- free of cheap mascot or placeholder branding
